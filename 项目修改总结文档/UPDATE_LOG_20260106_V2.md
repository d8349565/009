## 🔧 技术细节

### 总耗时Bug修复

**问题原因**:
- `PerformanceTimer.get_total_duration()` 可能返回 None
- 或者计时器未正确启动/结束

**解决方案**:
```python
# 使用安全的默认值处理
total_duration = self.timer.get_total_duration() if hasattr(self.timer, 'get_total_duration') else 0

# 确保总计时正确启动和结束
self.timer.start_total()  # 在系统开始时
# ... 执行任务 ...
self.timer.end_total()     # 在系统结束时
```

### 性能统计表格生成

**实现逻辑**:
1. 遍历 `timer.steps` 获取所有步骤记录
2. 按步骤名称分组统计（count, total_duration）
3. 计算平均耗时和时间占比
4. 格式化输出为对齐的表格

```python
# 统计步骤数据
step_stats = {}
for step in self.timer.steps:
    step_name = step['name']
    step_duration = step['duration']
    
    if step_name not in step_stats:
        step_stats[step_name] = {'count': 0, 'total_duration': 0}
    
    step_stats[step_name]['count'] += 1
    step_stats[step_name]['total_duration'] += step_duration

# 生成表格
for step_name, stats_data in step_stats.items():
    count = stats_data['count']
    total = stats_data['total_duration']
    avg = total / count
    percentage = (total / total_duration * 100)
    
    print(f"{step_name:<28} {count:<8} {total:>10.2f}s {avg:>13.2f}s {percentage:>13.2f}%")
```

## 💡 使用建议

### 1. 优化性能

根据性能统计表格，可以：
- 如果"步骤5-生成报告"占比过高（>70%）：
  - 考虑使用更快的模型
  - 启用 `SIMPLIFY_REPORT_INPUT=true`
  
- 如果"步骤3-执行搜索"占比过高（>30%）：
  - 减少搜索关键词数量
  - 优化搜索引擎配置

- 如果"步骤4-评估信息"占比过高（>20%）：
  - 增加 `MAX_CONCURRENT_EVALUATIONS`
  - 或启用 `SKIP_EVALUATION=true`

### 2. 模型配置调优

看到模型配置后，可以：
- 快速确认是否使用了预期的模型
- 检查是否启用了推理模式
- 对比不同方案的效果

### 3. 数据质量评估

通过 "收集数据条数" vs "有效条数"：
- 有效率 > 70%：数据质量好
- 有效率 < 50%：考虑调整搜索关键词
- 有效率 < 30%：可能需要启用优先搜索源
